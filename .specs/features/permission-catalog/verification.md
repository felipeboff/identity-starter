## Level and sampling judgment

- Every claim naming an HTTP status, error code or response shape (C1, C2, C3, C4, C8, C11, C12, C13, C17, C18, C19, C20, C22) has a proof that crosses the HTTP boundary: the `createIdentityHttp` route harness for the module e2e specs, and real HTTP against the started app (`request(url)`) for C11.
- C3 is proven on both routes, with a body that mixes the unknown code with a known code the actor does not hold, so the single `400` with `data.permissions: [unknown]` settles both "unknown codes only" and "before the holds check".
- C4 runs all four formats against both routes in one assertion loop.
- C5 is a use-case claim and is proven at that level. AC 5 names the command `pnpm identity:grant-admin`; no test runs the script. The script's wiring was read directly: `scripts/grant-admin.ts:7` imports `permissionCatalog` and `:59` passes it to identity, the same assembly `start` uses (`src/app/start.ts:39`, `:138`). That makes `src/app/permission-catalog.ts:5` the one shared assembly.
