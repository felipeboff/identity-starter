## Swept

- validation: existing - the TypeBox schema of `SignInWithEmailHandler` (`format: "email"`, password 1-128); C8 for the e-mail normalization in the throttle key
- failure modes: C1, C2, C10, C11, C12
- idempotency: n/a - each successful sign-in opens a new session by design (many sessions per account); a failed one changes nothing but the throttle counter, which C6 pins to one per attempt
- authorization: existing - public route behind `SIGN_IN_PER_IP` (20 per 15 min); C10, C11, C12 only answer after the right password
- concurrency: existing - the per-e-mail counter is the atomic Lua `INCR`/`PEXPIRE` of `RateLimiter.hit`, so concurrent failures each count once; the fixed window lets in-flight attempts finish, unchanged by this feature
- data lifecycle: existing - throttle keys expire with the 15-min window; the old mixed-case keys expire the same way, nothing to migrate
- dependency failure: existing - with Redis down, `RateLimiter` lets the attempt through and logs `shared.rate_limiter_unavailable`, unchanged
- state transitions: n/a - no entity changes state in this feature; account deactivation is only read
- observability: C9
